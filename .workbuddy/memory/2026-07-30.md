### 现有功能盘点（来源：mini-gateway/server.js，UI 内嵌于 renderDashboardHtml，行 1078-1441）

- 日志表无筛选无分页
- 深蓝底 #0b0f19 + 紫色渐变 Logo + 6 处 emoji，装饰压过信息
- 增删改仅用原生 confirm()，无 toast / loading / 错误反馈

## 实施阶段（编码 + 部署，2026-07-30 晚）

### 已落地改动（mini-gateway/server.js）
1. **后端轻量 keyHealth（纯内存，符合要求）**
   - 新增全局 `keyHealth = {}` + `KEY_COOLDOWN_THRESHOLD = 3`
   - `markKeyFail(providerId, keyIndex, status)` 累加 fails、置 `cooling`、记 lastFailAt/lastStatus
   - `markKeySuccess(providerId, keyIndex)` 重置 fails=0、state=`normal`
   - 错误统一入口 `recordErrorLog`（247 行）调用 markKeyFail；成功响应（2xx，949 行）调用 markKeySuccess
   - `GET /api/logs` 返回 `keyHealth`：masked 视图（含 id 末4位 + Key 风险提示），供前端画胶囊网格
   - 对齐 providerId 取值（`provider.id || provider.name`），两处 recordErrorLog 调用同步
   - 零依赖、零持久化、零启动开销，契合 Cloud Run 缩零

2. **UI 重写（renderDashboardHtml，设计稿→代码）**
   - 亮色单页纵向流：顶部栏（品牌+状态胶囊+退出）→ 运行概况卡（4 指标 + 内联 Base URL/API Key）→ Provider 卡片网格（名称/类型徽章/Base URL/**Key 胶囊网格** ≤4 个全铺开 + 模型标签）→ 可折叠日志区（搜索框 + 400/429/5xx chip + 提供商下拉 + 6 列表格 + 分页）
   - 前端 JS 全部单引号拼接，避免服务端模板字面量冲突；`/api/logs` 的 keyHealth 驱动胶囊渲染
   - 强调色 `#1A73E8`，Noto Sans SC + Roboto Mono，无 emoji

3. **修复 3 个原代码既有 bug（影响"配置 key"核心用途）**
   - `CONFIG_FILE_NAME` / `LOGS_FILE_NAME` 从未定义 → 保存配置、清空日志必崩；补常量 `config.json` / `error_logs.json`

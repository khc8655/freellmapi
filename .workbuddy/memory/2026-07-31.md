## 白屏 bug 修复（纯前端，不动后端）
- 症状：用户打开控制台空白。
- 根因：`<script>` 中 `localStorage` 裸调用在隐私模式/存储受限环境抛 SecurityError，整段脚本中断，`checkAuth()` 未执行，loginView/mainView/topbar 全停 `display:none` → 白屏。Node vm 实证：`[throw] SCRIPT_ERROR: SecurityError`。
- 修复（server.js）：
  1. localStorage 全量容错：新增 `lsGet/lsSet/lsDel` helper（try-catch），替换行 1369/1400/1404 三处裸调用。
  2. `loginView` 默认 `display:flex`（原 `none`）：兜底，即便 JS 崩也能见登录页。
- 部署：revision `freellmapi-00037-89d` (us-west1)，URL `https://freellmapi-559850716466.us-west1.run.app`。
- 验证：线上 `loginView` 默认 `display:flex`、`lsGet` 已部署；`/api/config`、`/api/logs` 无 token 仍 401（后端鉴权/功能全在）。

## 登录失败排查（token 问题，非代码 bug）
- 用户报"输入 token 无法登录"。实测：后端仅接受内置 ACCESS_TOKEN `6amm...1QN3`（curl /api/config 带此 token=200，wrong=401），Cloud Run env 未设 ACCESS_TOKEN。
- 根因：用户输入的并非该 token（疑似误用 config.md 里的 provider key / 别的串当 ACCESS_TOKEN）。原版能登用的也是这个内置 token。
- 改进：fetchData 401 时增加可见 toast 提示"ACCESS_TOKEN 错误，请重试"（原静默 logout 回登录页，用户无感知）。
- 部署：freellmapi-00038-dwj (us-west1)。
- 注：若要用自定义 token，需在 Cloud Run env 设 ACCESS_TOKEN；否则一律用代码内置 fallback。
